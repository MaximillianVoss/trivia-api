# Запуск из общей папки HW.Group-2

Дополнительный способ запуска через уже используемый `build-and-run.sh`. Индивидуальные команды из README и полного разбора остаются действительными.

## 1. Куда распаковать

Используйте `~/Desktop/HW.React/HW.Group-2`. `$HOME` автоматически подставляет домашнюю папку текущего пользователя Mac; в кавычках точки не нужно экранировать обратными слешами.

Распакуйте каждый ZIP отдельно и перенесите папку проекта целиком внутрь HW.Group-2. Существующие работы не заменяйте. Если одноимённая папка уже есть, оставьте её и распакуйте новую копию под другим именем — тогда измените путь в командах ниже.

```text
HW.Group-2/
├── build-and-run.sh
├── trivia-api/
│   └── package.json
├── github-repository-explorer/
│   └── package.json
├── bookstore-rest/
│   └── pom.xml
├── bookstore-data-rest/
│   └── pom.xml
└── ... прежние работы
```

Это четыре самостоятельных проекта. Новые Bookstore не нужно смешивать с прежним `03-spring-bookstore/bookstore`. В каждом проекте сохраняйте все файлы, в том числе скрытые `.mvn`, `.gitignore` и `.nvmrc`, если они присутствуют.

В общей папке не создавайте общий `package.json` или `pom.xml`: запускателю нужны отдельные корни проектов. ZIP следует распаковать — внутри архива скрипт проекты не ищет.

## 2. Открыть меню

```bash
cd "$HOME/Desktop/HW.React/HW.Group-2"
pwd
ls -l "./build-and-run.sh"
bash "./build-and-run.sh" --list
bash "./build-and-run.sh"
```

Правильное имя файла — **build-and-run.sh**. Вызов через `bash` работает без `chmod +x`. Сам запускатель должен находиться рядом с папками проектов: по умолчанию он ищет от своей папки, а не от случайного текущего каталога.

Найдите нужные названия в меню и введите их текущие номера через пробел или запятую. Номера меню меняются при добавлении проектов и не являются номерами заданий. Не выбирайте `all`, если не хотите также запускать прежние работы и Expo-проекты.

## 3. Запустить эту работу по имени

```bash
cd "$HOME/Desktop/HW.React/HW.Group-2"
bash "./build-and-run.sh" --project "trivia-api"
```

Запускатель должен распознать `trivia-api` как **Vite**. Это путь относительно HW.Group-2, а не GitHub-адрес. Если после распаковки получилась лишняя вложенность, укажите путь до папки с `package.json`, например `trivia-api/trivia-api`. Меню `--list` показывает фактический путь.

Несколько новых проектов одновременно:

```bash
bash "./build-and-run.sh" \
  --project "trivia-api" \
  --project "github-repository-explorer" \
  --project "bookstore-rest" \
  --project "bookstore-data-rest"
```

Только проверить и собрать текущую работу, без запуска серверов:

```bash
bash "./build-and-run.sh" --project "trivia-api" --build-only
```

Если скрипт хранится в другой папке, добавьте `--root "$HOME/Desktop/HW.React/HW.Group-2"`. Например, находясь рядом со скриптом:

```bash
bash "./build-and-run.sh" --root "$HOME/Desktop/HW.React/HW.Group-2" --project "trivia-api"
```

## 4. Адреса, зависимости и остановка

- React-проектам нужен Node.js 24 с npm. Скрипт установит зависимости по lock-файлу при необходимости, выполнит проверки и сборку.
- Bookstore нужен JDK 21 для рекомендуемой среды; Maven Wrapper включён. По умолчанию используется H2 — MySQL не нужен. Если ранее в текущем терминале включали MySQL-профиль, перед этими двумя проектами выполните `unset SPRING_PROFILES_ACTIVE`.
- Для Vite скрипт запускает **preview готовой сборки**, начиная с порта 4173. Это не dev-сервер 5173. Изменение исходников само по себе не обновляет preview: пересоберите проект или используйте индивидуальный `npm run dev`.
- Для Spring порты выбираются начиная с 8080; занятые порты пропускаются. Поэтому при общем запуске адрес может отличаться от индивидуальных примеров 8082/8083.
- Используйте именно адрес из итоговой таблицы скрипта. Для Bookstore точка входа — `/booklist`; API — `/books`, `/book/1`, а у Data REST дополнительно `/api/books` на том же фактическом порту.
- Общий запуск GitHub Explorer открывает финальную Bonus-версию. Для отдельных Step 1–3 сохранены индивидуальные команды `npm run dev:step1`, `npm run dev:step2`, `npm run dev:step3` из папки Explorer.
- Терминал оставьте открытым. **Control+C** останавливает серверы этого запуска; исходники и папки проектов не удаляются.

## Если проект не найден

1. Проверьте `pwd`, имя скрипта и `bash ./build-and-run.sh --help`.
2. Убедитесь, что ZIP распакован под HW.Group-2 и файл `package.json` либо `pom.xml` находится внутри папки нужного проекта.
3. Используйте фактический вложенный путь из `--list`; пути с пробелами заключайте в кавычки.
4. Если старая версия скрипта не знает `--project` или `--list`, используйте интерактивный запуск без флагов. Если и меню не находит проект, понадобится обновление самого запускателя; индивидуальные команды в README остаются рабочим запасным способом.

Инструкция ориентирована на сохранённую версию общего запускателя от 20.09.2026. Версия файла на конкретном Mac и реальный запуск на нём удалённо не подтверждены. Индивидуальные способы запуска не удалены.
