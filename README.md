# Trivia API

Учебный **React Web + TypeScript + Vite**: загрузка случайного вопроса по кнопке, обработка ограничения частоты API. [Условие](docs/ASSIGNMENT.md) · [Полное решение и объяснение](docs/MANUAL.md).

Маршрут: **подготовить Mac → клонировать → установить зависимости → проверить → запустить → объяснить код**.

## 1. Подготовить Mac

Нужны **Git**, **Node.js 24** и входящий в Node.js **npm**. Это обычный сайт React + TypeScript: Expo, Xcode Simulator, Android Studio, Java и MySQL для него не нужны.

Откройте Terminal и проверьте:

```bash
git --version
node --version
npm --version
```

Если Git не найден или macOS предлагает установить инструменты разработчика, установите **Command Line Tools**:

```bash
xcode-select --install
```

Дождитесь окончания системной установки, откройте новое окно Terminal и повторите `git --version`. Полный Xcode для этого сайта не требуется. [Инструкция Apple](https://developer.apple.com/documentation/xcode/installing-the-command-line-tools/).

Если Node.js отсутствует или установлена другая ветка, установите **Node.js 24 LTS** через официальный macOS Installer на [nodejs.org](https://nodejs.org/en/download). После установки перезапустите Terminal. Если у вас уже есть nvm, вместо установщика достаточно:

```bash
nvm install 24
nvm use 24
```

Не устанавливайте npm отдельно и не выполняйте `sudo npm install` в проекте.

## 2. Склонировать репозиторий

Следующие команды создают отдельную папку внутри `~/Projects`:

```bash
mkdir -p "$HOME/Projects"
cd "$HOME/Projects"
git clone https://github.com/MaximillianVoss/trivia-api.git
cd trivia-api
npm ci
```

Если папка с таким именем уже существует, не удаляйте её: перейдите в имеющийся клон или выберите другое имя, например `git clone https://github.com/MaximillianVoss/trivia-api.git trivia-api-copy`. В этом случае следующая команда — `cd trivia-api-copy`.

`npm ci` берёт точные версии из приложенного `package-lock.json`. Команда переустанавливает только зависимости в `node_modules`, не удаляет исходники. Все следующие команды выполняются из папки с `package.json`, не из родительского каталога.

Запланирован переход репозитория в private **26 сентября 2026 года в 12:00 по московскому времени (Europe/Moscow)**. Успейте склонировать до этого момента. Локальная копия продолжит работать после перехода; для нового клонирования и `git pull` затем потребуется приглашение владельца и авторизация. Сам этот README не меняет видимость репозитория.

## 3. Проверить и запустить

```bash
npm test
npm run build
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Если Vite напечатал другой порт, используйте адрес именно из терминала. Можно явно выбрать порт и открытие браузера:

```bash
npm run dev -- --port 5178 --strictPort --open
```

Адрес этой команды: [http://127.0.0.1:5178](http://127.0.0.1:5178). Если он тоже занят, выберите 5179; чужие процессы завершать не нужно. Между вариантами запуска остановите предыдущий сервер **Control + C**. Это останавливает сервер и **не удаляет папку проекта**.

Для просмотра собранной версии остановите dev-сервер и выполните:

```bash
npm run preview -- --port 4173 --strictPort --open
```

Адрес: [http://127.0.0.1:4173](http://127.0.0.1:4173). `preview` показывает каталог `dist` после `build`; это локальная проверка сборки, не публикация сайта в интернете.

## 4. Что проверять в приложении

1. До клика отображается приглашение получить вопрос; запроса к API нет.
2. Кнопка загружает один вопрос, на время ожидания недоступна.
3. После успеха вопрос заменяет начальное приглашение.
4. При HTTP 429 выводится предусмотренное сообщение об ограничении частоты.
5. Раскрываемый ответ, обработка HTML-сущностей, тайм-аут и сетевые ошибки — дополнительные улучшения.

`useState` хранит вопрос, ошибку и загрузку; `handleGetQuestion` запускает действие; `fetchQuestion` общается с API; `decodeHtml` превращает HTML-сущности в отображаемый текст. Полное объяснение — в [MANUAL](docs/MANUAL.md).

## Если что-то не запускается

| Сообщение / ситуация | Что сделать |
| --- | --- |
| `npm: command not found` | Установить Node.js 24, перезапустить Terminal. |
| `ENOENT package.json` | Перейти в папку клона, где лежит `package.json`. |
| `npm ci` требует lock-файл | Убедиться, что клонирован весь репозиторий: файл `package-lock.json` входит в него. |
| Git пишет `Repository not found` | Проверить адрес; после перехода в private запросить доступ у владельца. |
| `react/jsx-runtime` не найден | Запустить `npm ci` в корне и перезапустить редактор. |
| API недоступен | Проверить интернет; сообщение об ошибке не означает, что сайт не запустился. |
| В preview старый результат | После изменения исходников снова выполнить `npm run build`. |

После успешного клонирования интернет всё ещё нужен для установки зависимостей и реальных API-запросов. Тесты подменяют ответы API и не расходуют внешний лимит.

## Что сдавать и что объяснять

Изучите [условие без решения](docs/ASSIGNMENT.md), затем [полный разбор с листингами](docs/MANUAL.md). Объясните, где состояние, обработчик события, запрос и условный вывод. Сверьтесь с ручным чек-листом в разборе.

Клон этого репозитория — учебная основа, а не автоматическая сдача в Classroom. Для сдачи в репозиторий преподавателя переносите нужные файлы осознанно, сохраняйте его `.github` и правила проверок. Не отправляйте `node_modules`, токены, пароли или личные файлы.

Здесь не заявляется проверка на конкретном Mac или отправка работы преподавателю. Поле `"private": true` в `package.json` запрещает случайную публикацию npm-пакета и не определяет видимость репозитория GitHub.
